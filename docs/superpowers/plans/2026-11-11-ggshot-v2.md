# GG-Shøt-style v2 Backtest Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A causal, fee- and funding-aware portfolio backtest of a GG-Shøt-style momentum-breakout scanner on 15 Binance USDT-M perpetuals (30m + 1h), with in-sample selection and a one-shot out-of-sample verdict against the user's challenge bar.

**Architecture:** 1-minute futures candles (Binance bulk archive) are the single price source; 30m/1h/4h bars are resampled from them. The detector emits a *superset* of signals with their feature values once per coin/timeframe; each detector configuration is a filter on that superset. Each signal is resolved into a standalone trade per trade spec (entry, stop, target, fees, slippage, funding) on 1-minute data. A portfolio pass then applies the 3-slot / one-per-coin rule and the $5,000 → $5,500 / $4,700 challenge.

**Tech Stack:** Python 3.12, pandas, numpy, requests, pytest (all already in `requirements.txt`; no new dependencies).

**Spec:** `docs/superpowers/specs/2026-11-11-ggshot-v2-design.md` (research: `docs/research/ggshot-signals-analysis.md`)

## Global Constraints

- Work on a new branch `feat/ggshot-v2` created from the current HEAD. Stage files explicitly by path; the working tree also holds unrelated uncommitted CISD changes (`challenge_trader.py`, `core/analysis.py`, `core/config.py`, `models/backtest_cisd.py`, `tests/test_backtest_correctness.py`) that must **not** be committed by these tasks.
- Coins (also the tie-break order): BTC, ETH, SOL, BNB, XRP, DOGE, ADA, AVAX, LINK, DOT, LTC, NEAR, UNI, AAVE, FIL (`<COIN>USDT`, USDT-M perpetual).
- Timeframes: 30m and 1h only. Tie-break: 1h before 30m.
- Data period 2021-01-01 → latest closed candle. In-sample < 2025-01-01; out-of-sample ≥ 2025-01-01 (by signal decision time).
- Account $5,000; fail when equity touches **$4,700 (fixed)**; pass at **$5,500**. Main risk $20/trade, sensitivity $25.
- One stop, one target (2R or 3R). No partials, no breakeven, no trailing, no time exit.
- Max 3 open trades, max 1 per coin, across both timeframes in one account.
- Costs: taker 0.05% (`FEE_TAKER`) on entries and stops/end exits; maker 0.02% (`FEE_MAKER`) on take-profit; 2 bps adverse slippage on every taker fill; funding charged at each funding timestamp a trade is open through (longs pay positive rates).
- Intrabar: stop wins if stop and target fall in the same 1-minute bar.
- Only closed candles feed decisions; decisions happen at the signal bar's close.
- Selection uses in-sample only; ≤ 3 finalists (one reserved for the best post-close-confirmation config), each run once out-of-sample; nothing changes afterwards.
- All R / win-rate / P&L figures are net of fees, slippage and funding; a win = net P&L > 0.
- Cached market data (`data/futures/`) and run outputs (`reports/ggshot_v2/`) stay out of git.

## Review Focus

1. **Missing minutes / exchange outages** in 1m data → resampled bars must not invent prices; a 30m/1h bar with fewer than 90% of its minutes is dropped (no signal on it), and trade resolution simply continues on the next available minute. *Test added in Task 1.*
2. **Trade still open at the end of data** → closed at the last available close as reason `END`, taker fee; counted in stats, never silently dropped. *Test added in Task 4.*
3. **Price gaps through the stop** (open beyond stop) → filled at that open with slippage, so a loss can exceed 1R. *Test added in Task 4.*
4. **Structural stop on the wrong side of the entry or absurdly far** (swing/supertrend after a fast move) → widened to ≥ 1.0 ATR from entry; skipped if > 6 ATR or wrong side. *Test added in Task 4.*
5. **Coin listed after 2021-01-01 or a month missing from the archive** → that coin simply has no data for that span; downloads log the gap and the run continues. *Test added in Task 1.*

### Task 4: Trade resolution on 1-minute data

**Files:** Create `models/ggshot_v2/trades.py`; Test `tests/test_ggshot_v2.py`

**Interfaces:**
- Consumes: `detector.scan`/`apply_params` output rows, `data.load_1m`, `data.load_funding`, `config`.
- Produces:
  - `@dataclass(frozen=True) TradeSpec(stop_method: str, stop_k: float, target_r: float, entry: str = "next_open", confirm_minutes: int = 0, confirm_atr: float = 0.0)` — `stop_method` ∈ `{"swing", "supertrend", "atr"}` (`stop_k` used only for `"atr"`); `entry` ∈ `{"next_open", "confirm"}`.
  - `resolve_trades(signals: pd.DataFrame, m1: pd.DataFrame, funding: pd.Series, spec: TradeSpec, symbol: str, tf: str) -> pd.DataFrame` — one row per signal that gets a valid trade. Columns: `symbol, tf, side, signal_time, decision_time, entry_time, entry_px, stop_px, target_px, exit_time, exit_px, exit_reason ("TP"|"SL"|"END"), risk_px, r_gross, r_fee, r_funding, r_net, notional_per_risk` (= entry_px / risk_px). R values are per 1 unit of $ risk, so `$P&L = r_net × risk_usd` for any risk amount.

Rules (spec values):
- **Entry `next_open`:** the 1m bar opening at `decision_time`; price = its open × (1 + side × `SLIPPAGE`); taker fee.
- **Entry `confirm`:** trigger `L = close + side × confirm_atr × atr`; scan 1m bars with open time in `[decision_time, decision_time + confirm_minutes)`; first bar whose high ≥ L (long) / low ≤ L (short) fills at `L`, or at that bar's open if the open is already beyond `L`; then slippage + taker fee. No trigger → no trade.
- **Stop:** `"atr"`: `entry − side × stop_k × atr`. `"swing"`: `swing_low` (long) / `swing_high` (short). `"supertrend"`: `st_line`. For swing/supertrend: if on the wrong side of the entry or farther than 6 × ATR → skip; if closer than 1.0 × ATR → widen to 1.0 × ATR.
- **Target:** `entry + side × target_r × risk_px`; filled exactly at the target, maker fee, no slippage.
- **Exit search** (algorithm the tests don't determine): from the entry minute onward take the forward window (start 43,200 minutes, double until resolved or data ends); compute `cummax(high)` and `cummin(low)`; first stop index and first target index via `np.searchsorted` on these monotone arrays; the stop wins ties. On the stop bar, if the open is already beyond the stop, fill at the open; stop fills get slippage + taker fee. Unresolved at data end → `END` at the last close, slippage + taker fee.
- **Funding:** for funding times `t` with `entry_time < t ≤ exit_time`: `r_funding −= side × rate(t) × entry_px / risk_px` (use a cumulative sum + `searchsorted`).
- `r_fee = (FEE_TAKER × entry_px + exit_fee × exit_px) / risk_px`; `r_net = r_gross − r_fee + r_funding`.
